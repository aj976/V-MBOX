# M1 memory-source discovery — user-reported VM output

The operator ran `logman query providers`, `wevtutil ep`, and `wevtutil gp Microsoft-Windows-Threat-Intelligence /ge:true` in the Windows VM and supplied the output in chat. Both provider lists included `Microsoft-Windows-Threat-Intelligence`. Its reported GUID was `f4e1897c-bb5d-5668-f1d8-040f4d8dd344`; the metadata listed `KERNEL_THREATINT_TASK_PROTECTVM` and local/remote `PROTECTVM` keywords. These are metadata observations, not a captured protection-change event.

Subscription access from V-MBOX: not measured. Actual event delivery during a controlled memory-protection change: not measured. Required privileges or protected-process status for this VM: not measured. Collector overhead or loss for this provider: not measured.

Decision: exclude `MEM_PROTECT_CHANGE` from the validated M1 event set. Retain the observed Sysmon 7 (image load) and 10 (process access) as **memory-related proxies**. Sysmon 8 (remote thread) is configured but was not generated by the supplied benign simulation, so its end-to-end observability remains unverified. A later experiment can revise this decision only after a real event and access requirements are recorded; provider registration alone is insufficient.
